# 高性价比球员与阵容构建

这是一个基于 `data/FIFA 23 Players.csv` 的统计分析主题，目标不是单纯找“便宜球员”，而是把“低估球员识别”和“阵容构建”合并成一条可执行的分析链。

## 数据来源

数据文件来自 FIFA 23 球员资料汇总，包含球员能力值、身价、工资、位置、俱乐部、国家队与多项技术属性。文件位于：

`data/FIFA 23 Players.csv`

该文件共有 17,524 行、89 列。每一行代表一名球员。

## 分析目标

本主题围绕 **“如何从球员中找出统计意义上的高性价比球员，并据此组建一支预算受限但能力尽量高的球队”** 展开，产出 poster-ready 素材。

这里的“高性价比”不直接等于“低身价高能力”，而是先用模型控制位置、年龄、总能力、技能结构等因素，再用**残差 / 预测差**来定义“被低估”的程度。

### 1. 低估球员识别

先建立一个“市场定价模型”，用 `Value(in Euro)` 作为响应变量，解释变量包括：

- `Overall` 或 `TotalStats`
- 年龄 `Age`
- 位置 `Best Position` 或 `position_group`
- 身体素质类指标，如 `Pace Total`、`Physicality Total`
- 技术类指标，如 `Shooting Total`、`Passing Total`、`Dribbling Total`、`Defending Total` 

在控制这些变量后：

- **残差明显为负**：球员比模型预测得更便宜，可视为“被低估”
- **残差接近 0**：价格较符合模型预期
- **残差明显为正**：球员相对偏贵

### 2. 低估球员的能力结构

在识别出低估球员后，进一步比较他们的能力结构，回答：

- 哪些能力维度最常出现在“低估球员”身上？
- 不同位置的低估球员，短板是否不同？
- 某类球员的价值是否主要由少数能力维度驱动？

这一步更适合解释“训练优先级”，但只应表述为：

> 在本样本中，哪些能力与更高市场价值更相关，哪些短板最值得优先补强。

不要写成“训练这个一定会提升身价”，因为这仍然是观察性数据，不是干预实验。

### 3. 高性价比阵容构建

将低估球员进一步用于阵容构建。目标是：

- 在预算受限的前提下
- 满足位置搭配约束
- 让整队的“预测表现 / 总能力”尽量高
- 让整队的总身价尽量低

这一步可以把统计结果落到一个很直观的输出：

- 一套最优阵容名单
- 总预算
- 总预测价值或总能力
- 与“随机阵容”或“高身价阵容”的对比
- 与某几个俱乐部的最佳阵容的对比
- 与某几个国家队的最佳阵容的对比

## 建议的统计流程

### Step 1: EDA

先检查：

- 价格、工资是否右偏
- 是否存在大量 0 值
- 各位置的人数分布
- 各能力指标的分布与位置差异

### Step 2: 定义“被低估”

推荐用回归残差定义：

`log10(Value + 1) ~ TotalStats + Age + Position + Skill Structure + Physicality`

然后计算：

- `residual = observed - fitted`
- 或 `undervaluation = fitted - observed`

### Step 3: 低估球员筛选

可以考虑以下筛选规则：

- 残差处于最负的前 10%
- 或在同位置内残差最负的前 5%
- 并加上最小能力阈值，避免把“便宜但弱”的球员误当成高性价比

### Step 4: 构建“性价比评分”

可以定义一个综合指标，例如：

- `score = standardized(predicted_value) - standardized(observed_value)`
- 或 `value_per_euro = predicted_value / observed_value`
- 或结合位置权重的残差分数

### Step 5: 阵容优化

如果只想做一个可视化友好的版本，可以先做规则化选队：

- 每个位置选若干名残差最低且能力够高的球员
- 保证前锋、中场、后卫、门将数量平衡

如果想更正式一点，可以做整数规划：

- 目标函数：最大化总预测价值
- 约束：总身价不超过预算，且每个位置最少/最多若干人

## 建模建议

### 模型 1: 定价模型

`log10(Value + 1) ~ TotalStats + Age + Position + Skill variables`

用途：

- 估计球员的“理论身价”
- 找出被低估球员

### 模型 2: 训练优先级模型

只在低估球员子样本里再建模：

`log10(Value + 1) ~ Pace + Passing + Dribbling + Defending + Physicality + Shooting + ...`

用途：

- 判断低估球员最常缺的是哪类能力
- 形成“训练优先级”而不是因果训练建议

### 模型 3: 阵容评分模型

`score = predicted_performance - observed_value`

用途：

- 做选人排序
- 给整队构建一个清晰的评分标准

## 结论落点

这个主题的最终落点建议写成三层：

1. **识别谁被低估**
2. **解释这些球员为什么被低估**
3. **用这些球员组建一支预算友好的球队**

## 写给分析脚本的提示

- 数据文件名包含空格，读取时要直接引用完整路径。
- 先检查列名是否存在空格或括号，必要时在代码中统一重命名。
- `Value(in Euro)` 和 `Wage(in Euro)` 这两列可能需要先清理数值格式，再做分析。
- 如果使用对数模型，要先处理 0 值，因为 `log(0)` 不可用。
- 低估球员的定义必须基于同一套模型，避免先用一个模型筛人、再用另一个模型解释，造成口径不一致。
- 阵容构建时必须加位置约束，否则模型会只挑一类球员。
